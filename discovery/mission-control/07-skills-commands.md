## Overview

Mission Control has a **dual-command system** for AI agents:
1. **Plugin commands** (`commands/*/SKILL.md`) — for Claude Cowork plugin consumption
2. **Claude Code commands** (`.claude/commands/*/user.md`) — for Claude Code consumption

The `sync-commands.ts` module keeps these in sync with the agents and skills registry.

## Bidirectional Sync (`src/lib/sync-commands.ts`, 143 lines)

**Agent↔Skill bidirectional sync**:
- `syncAgentCommand()` generates `.claude/commands/<agent.id>/user.md` from `agents.json` + `skills-library.json` (resolved bidirectionally via `resolveLinkedSkills()`, L63-80)
- `syncSkillFile()` generates `skills/<skill.id>/SKILL.md` from skill definition
- Called from `/api/agents` POST/PUT

### Resolution Logic

```typescript
// L63-80
function resolveLinkedSkills(agent: AgentDefinition, skills: SkillDefinition[]) {
  // Skills where agent is in skill.agentIds
  const fromSkillSide = skills.filter(s => s.agentIds?.includes(agent.id));
  // Skills in agent.skillIds
  const fromAgentSide = skills.filter(s => agent.skillIds?.includes(s.id));
  // Union (deduplicated)
  return [...new Set([...fromSkillSide, ...fromAgentSide])];
}
```

This ensures that the relationship is maintained regardless of which side it's declared on.

## Orchestrator Command

`orchestrate/user.md` (67 lines) is the **meta-orchestrator**:
1. Reads `ai-context.md` (generated by `generate-context.ts`)
2. Groups pending tasks by assigned agent
3. Spawns sub-agents via Claude Code's `Task` tool
4. Supports parallel execution mode (calls `scripts/run-team.sh`)

## Parallel Execution

`scripts/run-team.sh` (75 lines) is a **parallel tmux orchestrator**:
- Launches one tmux pane per active agent (excluding "me")
- Each pane runs: `claude --print "$(cat .claude/commands/<id>/user.md)" 'Pick up your highest priority task and execute it...'`
- Usage: `tmux attach -t mc-agents`
